# دليل توحيد استجابات الـ API للـ Frontend

مرحباً بفريق الفرونت إند، لقد قمنا بتوحيد وتثبيت بنية الاستجابات الخاصة بجميع مسارات لوحة التحكم (Dashboard API) لتكون متسقة وتسهل عملية معالجة البيانات وتكاملها.

---

## 1. الهيكل العام للاستجابة (Standard Response Structure)

جميع استجابات الـ API ستأتي على الهيكل التالي كـ JSON object ثابت:

```json
{
    "status": true,
    "msg": "رسالة توضيحية للعملية",
    "data": null
}
```

* **`status`**: (Boolean) يعبر عن نجاح العملية (`true`) أو فشلها (`false`).
* **`msg`**: (String) نص توضيحي للعملية، يمكن عرضه للمستخدم مباشرة.
* **`data`**: (Object | Array | null) البيانات الفعلية المسترجعة من الخادم.

---

## 2. أنواع الاستجابات بالتفصيل

### أ. استجابة نجاح (Success Response)
عند نجاح طلب جلب بيانات، تحديث، أو إضافة:

```json
{
    "status": true,
    "msg": "تم جلب البيانات بنجاح",
    "data": {
        "id": 1,
        "name": "اسم العنصر"
    }
}
```

### ب. استجابة نجاح مع ترقيم الصفحات (Paginated Response)
لجلب القوائم التي تحتوي على ترقيم صفحات عند إرسال المعامل `?page=1`:

```json
{
    "status": true,
    "msg": "تم بنجاح",
    "data": {
        "items_key": [
            { "id": 1, "name": "العنصر الأول" },
            { "id": 2, "name": "العنصر الثاني" }
        ],
        "pagination": {
            "current_page": 1,
            "last_page": 5,
            "per_page": 15,
            "total": 75,
            "from": 1,
            "to": 15
        }
    }
}
```
*ملاحظة: الاسم الممثل للمصفوفة (مثل `items_key`) يعتمد على نوع الكيان المسترجع (مثلاً: `users`, `courses`, `exams`, `students`, إلخ).*

### ج. استجابة خطأ غير موجود (Not Found - 404)
عند طلب عنصر غير متوفر في قاعدة البيانات:

```json
{
    "status": false,
    "msg": "الطلب غير موجود أو تم حذفه",
    "data": null
}
```

### د. استجابة خطأ في التحقق من البيانات (Validation Error - 422)
عند إرسال بيانات غير صالحة أو ينقصها حقول مطلوبة:

```json
{
    "status": false,
    "msg": "خطأ في البيانات المرسلة",
    "data": {
        "email": [
            "البريد الإلكتروني مستخدم بالفعل."
        ],
        "password": [
            "حقل كلمة المرور مطلوب."
        ]
    }
}
```

### هـ. استجابة خطأ عام (Bad Request / Unauthorized - 400 / 401 / 403)
عند حدوث مشكلة عامة أو صلاحيات غير كافية:

```json
{
    "status": false,
    "msg": "غير مصرح لك بإجراء هذه العملية",
    "data": null
}
```

---

## 3. ملاحظات هامة للتعامل مع الـ API

1. **التحقق من حالة الطلب**: يفضل الاعتماد على قيمة المفتاح `status` داخل الـ body لتحديد نجاح أو فشل العملية، بالإضافة إلى حالات الـ HTTP Status Codes القياسية (مثل `200`, `201`, `400`, `401`, `403`, `404`, `422`).
2. **الرسائل المباشرة**: قيمة `msg` دائماً تحتوي على رسالة واضحة باللغة العربية أو الإنجليزية تعبر عن تفاصيل نجاح أو فشل العملية ويمكن استخدامها مباشرة في التنبيهات (Toasts / Alerts) للمستخدمين.
